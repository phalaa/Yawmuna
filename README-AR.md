# يومنا — النسخة السحابية 3.0

تطبيق عربي لتنظيم أعمال الأطفال، بمهام متكررة ونجوم ومكافآت وسجل أسبوعي وخمسة ألوان تتغير حسب ساعة الجهاز.
هذه نسخة مستقلة للرفع على GitHub. لا تعتمد على ChatGPT ولا تحتاج تسجيل الدخول إليه.

## ما الذي تحتاجه؟

- حساب GitHub لاستضافة الملفات والواجهة عبر GitHub Pages.
- مشروع Supabase: قاعدة PostgreSQL + تسجيل دخول العائلة.
- بريد وكلمة مرور لحساب العائلة داخل التطبيق. استخدم الحساب نفسه على الكمبيوتر وشاشة اللمس والهاتف لمشاهدة البيانات نفسها.

الملفات جاهزة للربط، لكنها ليست متصلة بمشروع حقيقي بعد. لا توجد كلمات مرور أو مفاتيح سرية داخل الحزمة. النسخة المنشورة القديمة لم تتغير.

## 1. احتفظ ببياناتك القديمة

افتح التطبيق القديم من المتصفح والجهاز اللذين يحتويان بياناتك:
https://family-day-board.alaa-alghazzi2.chatgpt.site
من «إدارة العائلة» اختر «تنزيل نسخة احتياطية». احفظ ملف JSON قبل نقل التطبيق.
لا يمكن للموقع الجديد قراءة بيانات الموقع القديم تلقائيًا لاختلاف عنوانه.

## 2. إنشاء قاعدة PostgreSQL على Supabase

1. افتح https://supabase.com/dashboard وأنشئ مشروعًا جديدًا، مثل `yawmuna`.
2. اختر الخطة المجانية إن كانت متاحة لحسابك. احفظ كلمة مرور قاعدة البيانات في مكان خاص؛ لا تضعها في ملفات GitHub.
3. بعد جاهزية المشروع، افتح **SQL Editor → New query**.
4. افتح الملف `database/setup.sql` المرفق، وانسخ محتواه كله إلى المحرر واضغط **Run**.
5. ستجد جدول `public.yawmuna_boards` ودالة `public.yawmuna_save`. السكربت يفعّل حماية الصفوف RLS ويحدد ملكية البيانات لكل حساب.
6. من **Authentication → Users → Add user → Create new user** أنشئ حساب العائلة ببريدك وكلمة مرور قوية. فعّل **Auto Confirm User** إن ظهر حتى لا تنتظر رسالة بريد في التجربة الأولى. لا تنشئ المستخدم بإدخال SQL يدوي في جدول auth.users.
7. من إعدادات Authentication تأكد أن الدخول بالبريد وكلمة المرور مفعّل. التطبيق لا يعرض التسجيل الذاتي؛ يمكنك تعطيل تسجيل حسابات جديدة وإضافة حسابات العائلات من لوحة التحكم فقط.
8. إذا نسيت كلمة المرور في النسخة التجريبية، يديرها مسؤول المشروع من Authentication؛ لم تُضف واجهة استعادة بالبريد في هذه النسخة.

## 3. إدخال إعدادات الربط

من نافذة **Connect** أو إعدادات المشروع **API / API Keys** انسخ:
- Project URL على شكل `https://xxxx.supabase.co`.
- المفتاح **Publishable** الذي يبدأ بـ `sb_publishable_`؛ يدعم التطبيق مفتاح `anon` القديم أيضًا.

افتح `config.js` بالمفكرة، وأدخل القيمتين:

```js
window.YAWMUNA_CONFIG = {
  supabaseUrl: "https://YOUR_PROJECT.supabase.co",
  supabasePublishableKey: "sb_publishable_YOUR_KEY"
};
```

المفتاح Publishable مصمم للظهور في الواجهة؛ الحماية تأتي من حساب المستخدم وسياسات RLS. لا تستخدم `service_role` أو `sb_secret_` أو رابط اتصال PostgreSQL أو كلمة مرور قاعدة البيانات في هذا الملف أو GitHub.

## 4. رفع الملفات على GitHub واستضافة الموقع مجانًا

1. فك ضغط الحزمة.
2. افتح https://github.com/new وأنشئ مستودعًا باسم `yawmuna`.
3. اختر **Public** إذا كنت تريد GitHub Pages على خطة GitHub Free. كود التطبيق سيكون عامًا، لكن بيانات العائلة في Supabase لا تصبح عامة.
4. اختر **Add file → Upload files** وارفع محتويات مجلد `Yawmuna-Cloud`، وليس ZIP ولا المجلد الأب. يجب أن يظهر `index.html` في جذر المستودع.
5. ارفع مجلد `vendor` أيضًا؛ يحتوي نسخة محلية مثبتة من مكتبة Supabase. لا ترفع `node_modules`.
6. اضغط **Commit changes**.
7. افتح **Settings → Pages**.
8. عند **Source** اختر **Deploy from a branch**، ثم الفرع **main** والمجلد **/(root)**، واضغط **Save**.
9. انتظر نجاح النشر. ستجد الرابط في صفحة Pages، عادة `https://YOUR_USERNAME.github.io/yawmuna/`.
10. افتح الرابط، وأدخل بريد حساب العائلة وكلمة مروره اللذين أنشأتهما في Supabase.

لا تحتاج خادم Node.js لاستضافة هذه النسخة ولا تحتاج أوامر build؛ ملفات التشغيل والمكتبة جاهزة. GitHub Pages يقدم الواجهة فقط، وSupabase يقدم قاعدة PostgreSQL وواجهة API وتسجيل الدخول.

## 5. نقل البيانات وتجربة جهازين

1. سجّل الدخول إلى النسخة الجديدة.
2. من «إدارة العائلة → استيراد نسخة» اختر ملف JSON الذي نزلته من التطبيق القديم.
3. الاستيراد يستبدل لوحة هذا الحساب بالكامل على جميع أجهزته. صدّر نسخة من اللوحة الحالية أولًا إذا كانت تحوي بيانات.
4. انتظر ظهور «محفوظ في السحابة» قبل إغلاق الصفحة.
5. افتح الموقع على جهاز آخر وسجّل الدخول بالحساب نفسه. تظهر المهام والمكافآت نفسها.
6. أنجز مهمة على الجهاز الأول؛ تُفحص تحديثات السحابة على الثاني كل 10 ثوانٍ، وعند العودة إلى الصفحة. يُؤجّل التحديث أثناء فتح نافذة تعديل.
7. عند انتهاء العمل على جهاز مشترك اختر «خروج».

## طريقة الحفظ وحدود النسخة

- كل حساب بريد يملك لوحة عائلية مستقلة. لا توجد أدوار مدير/طفل منفصلة؛ كل من يدخل حساب العائلة يستطيع إدارتها.
- الحفظ السحابي يحتاج الإنترنت. عند فشل الحفظ يبقى التعديل المعلّق في المتصفح، وتظهر خيارات إعادة المحاولة وتنزيله أو العودة إلى نسخة السحابة.
- إذا عدّل جهازان نسخة قديمة في الوقت نفسه، يُرفض الحفظ الثاني حتى لا يمحو التعديل الأحدث. نزّل التعديل المعلّق، حمّل نسخة السحابة ثم أعد تنفيذ التعديل المطلوب. لا يحدث دمج تلقائي.
- عند تحميل النسخة السحابية بعد تعارض، لا تستورد النسخة المعلقة كاملة إلا إذا كنت تقصد استبدال جميع بيانات السحابة.
- ينتظر التطبيق تأكيد الحفظ قبل السماح بالتعديل التالي. لا يُعامل فشل الشبكة على أنه حفظ ناجح.
- البيانات موجودة داخل عمود JSONB في PostgreSQL؛ كل لوحة تُحفظ ذريًا برقم إصدار. هذا مناسب للتجربة العائلية، وليس نظام تقارير علائقيًا كبيرًا.
- التاريخ والألوان يعتمدان ساعة الجهاز. تعديل المهام المتكررة يغيّر الجدول المعروض، بينما تبقى إنجازات الأيام السابقة في السجل.
- لا تتضمن الحزمة بياناتك الشخصية الموجودة في المتصفح القديم.
- Supabase ليس مجرد PostgreSQL خام: هذه النسخة تستخدم Auth وData API منه. استخدام Neon أو PostgreSQL عام يحتاج خادم API ودخول بديلين.

## تشخيص مشاكل التشغيل

- شاشة «خطوة واحدة قبل البدء»: أكمل `config.js` ثم حدّث الصفحة.
- «لم تجهّز قاعدة البيانات»: نفّذ `database/setup.sql` في المشروع نفسه الموجود في config.js.
- فشل الدخول: تحقق من البريد وكلمة المرور وتأكيد المستخدم في Authentication.
- عدم ظهور البيانات على جهاز آخر: تأكد من استعمال حساب العائلة نفسه ومن اكتمال الحفظ، ثم انتظر 10 ثوانٍ.
- فقدان الإنترنت أثناء الحفظ: لا تمسح بيانات المتصفح؛ استخدم إعادة المحاولة أو نزّل التعديل المعلّق.
- لا تفتح `index.html` بالنقر المزدوج. استعمل GitHub Pages أو خادمًا محليًا: `python -m http.server 8080` ثم http://localhost:8080.
- لا توجد ضمانة لوصول أي مزود من كل الشبكات والبلدان؛ اختبر الرابط والاتصال بـSupabase من شبكتك الفعلية.

## الملفات

- `index.html`, `style.css`, `app.js`: واجهة يومنا والمهام والمكافآت.
- `theme.js`: الفجر 05–08، الصباح 08–12، الظهر 12–16، المساء 16–20، الليل 20–05.
- `cloud.js`: دخول ومزامنة ومنع تعارض الكتابة وحفظ التعديلات المعلقة.
- `config.js`: إعدادات مشروعك العامة.
- `vendor/supabase.js`: المكتبة المرفقة للتشغيل دون CDN خارجي.
- `database/setup.sql`: الجدول والسياسات ودالة الحفظ.
- `tests/`: اختبارات قاعدة البيانات وتكامل الواجهة.
- `package.json`, `package-lock.json`, `vendor-entry.js`: إعادة بناء المكتبة وتشغيل اختبارات المطور.

للمطور فقط: `npm ci` ثم `npm test`. لإعادة بناء المكتبة: `npm run build:vendor`.

## التحقق والمراجع

اختُبر سكربت SQL باستخدام PGlite، وهو PostgreSQL يعمل محليًا عبر WebAssembly: عزل الحسابات، منع الزائر غير المسجل، منع تعديل الملكية، رفض الإصدار القديم، إعادة المحاولة دون تكرار، وإعادة تشغيل الإعداد دون حذف البيانات. لا تعادل هذه الاختبارات تجربة فعلية لمشروع Supabase خارجي؛ يلزم تنفيذ خطوات جهازين بعد إدخال إعدادات مشروعك.

مراجع رسمية تمت مراجعتها في 15 نوفمبر 2026:
- GitHub Pages: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site
- Supabase Auth: https://supabase.com/docs/guides/auth/passwords
- حماية الصفوف: https://supabase.com/docs/guides/database/postgres/row-level-security
- الأسعار: https://supabase.com/pricing

وقت المراجعة: GitHub Pages متاح للمستودعات العامة على GitHub Free، وخطة Supabase المجانية توفر 500 MB للقاعدة وقد يتوقف المشروع مؤقتًا بعد أسبوع من عدم النشاط؛ راجع حدود خطتك عند الإنشاء. لا تتطلب هذه الحزمة شراء خطة مدفوعة للتجربة الأساسية.
